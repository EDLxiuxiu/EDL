# 数据库字段说明

主系统数据库为 admissionsim_app。历史样例库 admissionsim 和独立实验库 admissionsim_scale_150000 保留原结构。schema_app.sql 是主系统精确 DDL；下表解释字段语义。所有编号、名称和个人数据均为虚构数据。

## 输入版本中的逻辑实体

| 路径 | 字段 | 约束与含义 |
| --- | --- | --- |
| junior_schools | 学校编号到名称的映射 | 编号为 1 至 24 位字母数字下划线；名称不为空 |
| senior_schools | name 与 general_batch | 名称；统招接收批次仅为 3 或 4 |
| candidates | id、name、junior、score、tie | 唯一考生号、虚构姓名、初中、非负整数分数、相同分数内唯一正整数序号 |
| candidates | choice | 第一批高中编号或空字符串 |
| candidates | second_choices | 按志愿顺序存储，最多 3 校，必须有本初中指标 |
| candidates | choices 的 3 与 4 | 第三、四批有序志愿，各最多 6 校，不重复 |
| plans | 计划号到 seats、cutoff 的映射 | 初始名额；计划控制线；如 2-A-J1 表示 A 高中给 J1 初中的第二批计划 |
| autonomous_ranks | 高中到考生排名的映射 | 只保存合格者，校内排名唯一；不在名单表示没有该校资格 |
| config | 年度、种子、规模和生成参数 | 记录来源；已生成数据不得静默改写 |

导入与编辑先校验结构和引用。创建运行时再校验计划控制线不低于该次全市控制线。年度、控制线、第一梯度及间隔固定到 app_runs.rules。

## app_datasets

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| dataset_id | CHAR(36) | UUID 主键，修改时创建新 UUID |
| parent_id | CHAR(36) 可空 | 来源版本，自引用外键 |
| label | VARCHAR(200) | 页面名称 |
| content_sha | CHAR(64) | 规范 JSON 的 SHA256，读取时复核 |
| candidate_count | 无符号整数 | 考生数量摘要 |
| payload | LONGBLOB | zlib 压缩的完整输入聚合，不是加密 |
| created_at | TIMESTAMP(6) | 创建时间 |

## app_runs 与 app_checkpoints

| 表 | 字段 | 说明 |
| --- | --- | --- |
| app_runs | run_id、dataset_id | 运行主键、不可变输入外键 |
| app_runs | rules、provenance | 规则 JSON；源码哈希、Git HEAD 及模型版本 |
| app_runs | completed_batch | 0 至 4，同时作为条件更新版本号；状态为待运行、部分完成或四批完成 |
| app_runs | candidate_count、admitted_count、remaining_seats | 人数和余额冗余；和每批状态同事务更新 |
| app_runs | created_at、updated_at | 创建及最近推进时间 |
| app_checkpoints | run_id、batch_no | 复合主键，保存第 0 至 4 批状态 |
| app_checkpoints | state_sha、payload | 完整状态的摘要；zlib 压缩的名单、顺序、余额、结转及全部日志 |

第 0 批表示尚未执行投档。提交响应异常后，以持久 completed_batch 和对应检查点为准。应用不提供原地更新或删除历史输入、已完成检查点的功能。

## app_candidate_results

| 字段 | 说明 |
| --- | --- |
| run_id、candidate_no | 复合主键；一次运行一名考生恰好一条状态记录 |
| name、junior_code、score、tie_no | 该次快照中的考生信息，用于索引和汇总 |
| admitted_batch、senior_code、plan_id | 已录取时分别为批次、高中、计划；未录取时全部为空 |
| admission_order、choice_no | 计划内实际录取顺序、录取志愿序号；未录取时为空 |
| payload | 该考生完整输入、录取位置、四批处理文本和结构化余额事件 JSON |

联合唯一键 run_id、plan_id、admission_order 保证计划内顺序唯一。索引按 run_id 加 junior_code、senior_code 与 admitted_batch 服务多维查询。payload 中冗余与结构化列必须同事务更新；audit 全量比较两者及检查点。

新增覆盖索引 ix_candidate_batch 包含 run_id、admitted_batch、candidate_no。它服务分批计数和未录名单读取；全运行统计的未录名单 SQL 在实际诊断后明确使用该索引，避免优化器为排序选择宽主键记录。现有主库可重新执行 init-db 幂等补充这个索引，不重建录取结果。

界面汇总另用 ix_candidate_statistics 覆盖 run_id、junior_code、score、admitted_batch，避免按生源初中分组时通过原初中索引大量回表读取宽记录；分数分布也可扫描该窄索引。两条界面 SQL 使用明确索引，原先的执行计划、单次诊断及修正后的结果核对单独保留，不冒充三轮基准中位数。

## app_plan_results

| 字段 | 说明 |
| --- | --- |
| run_id、plan_id | 复合主键 |
| batch、school、junior | 计划批次、高中；junior 只用于第二批来源 |
| initial_seats | 原始名额，不因结转改变 |
| transferred_in、transferred_out | 本次运行截至当前批次的累计转入、转出 |
| admitted_count、remaining_seats | 截至当前已提交批次的录取数与余额 |
| lowest_score | 已录取者最低分，无人录取为空 |
| last_id、last_score、last_choice、last_tie | 实际末位考生及分数、志愿、同分序号；无人录取为空 |

CHECK 约束初始加转入等于转出加录取加余额，采用两端加法避免无符号整数减法。内部转入、转出只改变批次计划间分布，不增加全市原始名额。

## app_transfers

| 字段 | 说明 |
| --- | --- |
| run_id、transfer_no | 运行内连续流水序号，复合主键 |
| source_plan_id、target_plan_id | 计划外键，来源只允许第一、二批，目标必须是同校第三批 |
| seats | 正整数结转人数 |

来源和方向的业务约束由领域校验及完整核对执行；不能仅凭外键推断所有投档规则已由数据库保证。
