## 规模核对

本地新实现使用原 150000 人数据及其 manifest，核对全部计划名单与顺序、余额、结转及全部文本日志。完整结果摘要与历史参考相同，表明该次输入下业务及文本日志一致；结构化余额事件属于新增查询数据，不包含在旧全文摘要中，另由投影和事件测试验证。

不要将新实现的单次正确性验收耗时与旧三轮中位数比较后宣称收益。MySQL 优化对照使用同一数据、六类考生、相同旧字段统计口径、预跑和正式次数；优化后读取新增结构化记录。报告总耗时是客户端墙钟时间，不是服务器单条 SQL 时间。

## 故障记录原则

数据库实际故障另存新报告，记录阶段、时间、已知 UUID 和可核查状态。出现连接丢失不自动断定未提交。真实回滚、真实恢复和并发 MySQL 实测必须由对应数据库记录证明；当前模拟连接与内存测试只证明代码路径，不代替这些实验。

本轮真实故障验收已经另有通过报告：它验证提交前异常的整批回滚，以及更换连接与 Service 后从持久检查点继续；不把“新建 Service”描述成已经实际强杀 Windows 进程。并发控制用真实陈旧请求验证版本条件，不将它冒充高并发压力实验。

查询 v3 之后修复了仅位于界面分数分布的 GROUP BY 表达式，并补充界面汇总用覆盖索引；投档、考生点查及全计划基准函数语义没有改变。各报告保留自身执行时的源码和索引记录，最终交付核对另记录版本差异，不篡改旧 SHA。

app_web_statistics_index_v1 保留界面索引前后的执行计划、单次诊断和结果一致性核对。初中汇总的单次诊断约 30.38 秒到 0.59 秒；它与三轮完整查询报告是不同口径，不混用。默认 unittest discover 会跳过两项真实 MySQL 测试；它们已在显式授权环境中分别实际运行，不能把默认跳过写成再次通过。
